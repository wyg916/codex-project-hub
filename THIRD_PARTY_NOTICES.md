The Windows installer also pins the build/install toolchain to pip 26.2.1 and setuptools 84.0.0; both are MIT-licensed.

`backend/pylock.toml` is a PEP 751 lock generated by pip 26.2.1 for CPython 3.11 on Windows x86-64. It pins every resolved application/test package to a specific artifact URL and SHA-256 hash. pip currently labels this lock support experimental, and the file is intentionally platform-specific; regenerate and audit it whenever a direct requirement pin or the supported Python/platform changes. The reproducible procedure is documented in `CONTRIBUTING.md`. The pip/setuptools bootstrap trust boundary is separately pinned by the installer and its bootstrap requirements file. ## Fonts, icons, screenshots, and other assets

- The application does not currently bundle a font file or load a remote web font. Its CSS uses a system-font fallback list.
- Navigation icons are Unicode characters rather than a redistributed icon pack.
- Public screenshots must be captured from the running application with synthetic data and stored under `docs/images/` with documented provenance.
- Internal concept images, generated UI mockups, private screenshots, and unverified delivery-package assets are not approved for redistribution and must not be included in a public release.

## Distribution checklist

Before release:

1. Verify that `LICENSE`, `NOTICE`, package metadata, and release metadata all identify Apache-2.0 consistently.
2. Regenerate and verify the Python and npm lock files, and optionally export an SBOM from the exact release environment.
3. Preserve all required license texts, copyright notices, and attribution.
4. Inspect the production build to determine which dependency code or data is actually redistributed.
5. Record the author, source, permission, and privacy review for every public image or other non-code asset.

This inventory is an engineering aid and not legal advice.
